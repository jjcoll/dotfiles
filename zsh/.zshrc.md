# zsh — decisions

Rewrite date: 2026-09-03. Startup went **1.05s → 0.06s** per shell (warm; the
first shell after a config change pays ~0.5s to rebuild `~/.zcompdump`).

That number matters more than it looks: herdr/tmux start a fresh interactive
shell for every pane, so this was a full second of dead time per split.

## Measurements that drove it

Each block timed in isolation with `zsh -f -c '<block>'`:

| Block | Cost | Verdict |
|---|---|---|
| nvm eager source | 0.91s | lazy |
| conda init hook | 0.41s | lazy |
| oh-my-zsh + 3 plugins | 0.16s | removed |
| gcloud completion | 0.05s | kept |
| p10k config | ~0.00s | deleted (inert, see Prompt) |

## What was removed, and why

**oh-my-zsh.** A 28MB framework doing three things: setting history/completion
options, adding the `git` plugin's ~150 aliases, and sourcing two plugins that
are plain git clones. A grep of 10,537 history entries found **zero** uses of
any omz git alias (`gst`, `gco`, `gp`, …). The history/completion options it set
are now ~10 explicit lines in `.zshrc`; the two plugins moved to
`~/.zsh/plugins/` and are sourced directly.

`~/.oh-my-zsh` was deleted afterwards, along with `~/.p10k.zsh`. Reinstalling
omz is a `curl | sh`; a p10k config is regenerable with `p10k configure`.

**`ZSH_THEME="candy"`.** Not removed for being slow — removed with the framework.
Worth recording *why the old setup was confusing*: candy was the real prompt all
along. `~/.p10k.zsh` (91KB) only sets p10k's configuration variables; the theme
itself is loaded by `ZSH_THEME=powerlevel10k/powerlevel10k`, which was commented
out. So the p10k instant-prompt block at the top of the old file guarded a theme
that never loaded, and the 91KB of config had no effect.

**Eager nvm.** Sourced ~100KB of shell functions plus a bash-completion file in
every shell, so `nvm` would exist and node would be on PATH. History: `nvm` 37
times, `npm` 1065. Now the default version (`~/.nvm/alias/default`) goes on PATH
directly and `nvm` is a one-line shim that sources `nvm.sh` on first call and
re-runs itself. `node`/`npm` are instant; the first `nvm use` in a shell pays the
0.9s once. **If you change the default with `nvm alias default`, open a new
shell** — PATH is computed at startup.

**Eager conda.** Ran the conda binary at every startup to install its shell hook.
`~/.condarc` has `auto_activate_base: false`, `python3` is homebrew's, and conda
appears 13 times in the whole history. Same shim treatment. `conda activate`
works from the first call.

## Prompt

**starship** (`~/.config/starship.toml`, tracked). Reached for after a few days
of plain `%~`, because the one thing genuinely missing was the git branch, and
hand-rolling `vcs_info` to get it is more code than a TOML file.

It replaces only the prompt — it is not a framework, and nothing else depends on
it. `.zshrc` falls back to the plain zsh prompt if the binary is absent, so a
fresh machine boots fine before `brew install starship`.

Shows: last two path segments, branch, git status, command duration over 2s,
non-zero exit code, `%`, and a dim clock on the right. The default preset also
renders node/python/cloud/package versions; the explicit `format` string leaves
them out, since a prompt that changes width per directory is harder to scan.

**Cost.** Startup went 0.06s → 0.08s (one `eval` at init). The per-prompt render
is the real number: ~40ms in a small repo, ~127ms in a 2,452-file one. The git
status module is nearly all of it — without it the same big repo renders in
27ms. If a large repo ever feels laggy, `[git_status] disabled = true` is the
knob, and the branch name stays.

Alternatives, if starship ever gets in the way: `vcs_info` ships with zsh (~8
lines, synchronous), and powerlevel10k is a plain git repo you can clone and
source — it never needed oh-my-zsh either; omz was only ever the loader.

## Landmines

- **gcloud SDK lives in `~/Downloads/google-cloud-sdk`.** The day that folder gets
  cleaned out, `gcloud` vanishes. Sourcing is guarded so the shell won't error,
  it will just silently lose the command. Move it to `~/.local/` and re-run
  `gcloud init` when there's a spare minute.
- **`compinit -C`** skips the insecure-directory audit for speed; the dump is
  rebuilt when older than 24h. If a new tool's completions don't show up,
  `rm ~/.zcompdump && exec zsh`.
- **Secrets stay in `~/.zshrc.local`**, which is outside this repo and untracked
  by design. `.zshrc` sources it last if present. Never move those exports here.

## Layout

```
~/.zshrc                  → symlink to ~/.config/zsh/.zshrc  (was a diverged copy)
~/.config/zsh/.zshrc      tracked
~/.config/zsh/.zshrc.md   this file
~/.zsh/plugins/           autosuggestions + syntax-highlighting (git clones, untracked)
~/.zshrc.local            secrets, untracked
~/.zshrc.bak              pre-rewrite backup
```

The tracked copy had drifted from the live file since May 2026 because `~/.zshrc`
was a real file, not a symlink. It is a symlink now, so the repo can't go stale
again.
